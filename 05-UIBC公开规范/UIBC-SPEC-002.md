## 〇、一句话摘要

> 给一个自治智能体"上户口"——证明它从哪来、做过什么、能不能改，三件事缺一不可。

---

## 第 1 章 范围与术语

### 1.1 适用范围

本规范适用于任何需要证明自身身份、行为可追溯、变更受控的智能体系统，包括：

- 独立运行的自治智能体（个人助理、企业代理）
- 多智能体协作网络中的成员节点
- 由智能体生成或演化的子智能体（"AI 造 AI"场景）
- 承载长期记忆、需要跨设备迁移的智能体

不适用：无状态的一次性推理调用（如单纯的文本生成 API 调用）。

### 1.2 术语定义

| 术语 | 定义 |
| --- | --- |
| 三律 | 有籍（出生登记）、有证（证据工件）、有门禁（变更放行）三条基本要求 |
| 有籍 | 智能体拥有唯一、可验证的身份记录，含来源、版本、权属 |
| 有证 | 智能体的关键行为产生可独立验证的证据工件 |
| 有门禁 | 智能体的变更（升级、能力扩展、权限调整）须经受控放行 |
| 户口（Manifest） | 承载"有籍"的结构化文件 |
| 证据工件（Evidence Artifact） | 承载"有证"的可验证产物 |
| 放行记录（Gate Record） | 承载"有门禁"的变更审批痕迹 |

---

## 第 2 章 三律模型（核心）

本规范以三律作为智能体可治理性的判定框架。三律之间是并列且互相支撑的关系，缺一即不成立。

### 2.1 有籍（Identity）

| 要求 | 说明 | 符合性判据 |
| --- | --- | --- |
| I1 唯一标识 | 智能体有全局唯一的标识符 | 存在 agent_id 且全局唯一 |
| I2 来源可查 | 记录创建者、创建时间、生成方式 | 存在来源字段 |
| I3 权属明确 | 明确归属主体（个人/组织） | 存在权属字段 |
| I4 版本可溯 | 记录版本号与版本谱系 | 存在版本字段与变更记录 |
| I5 能力声明 | 声明自身能力边界与所需权限 | 存在能力清单 |

### 2.2 有证（Evidence）

| 要求 | 说明 | 符合性判据 |
| --- | --- | --- |
| V1 关键行为留痕 | 关键操作产生记录（非全量，但关键节点必留） | 存在行为日志 |
| V2 不可篡改 | 记录具备完整性校验 | 存在哈希/指纹 |
| V3 可独立验证 | 第三方可在不信任发布方的前提下验证 | 存在验真机制 |
| V4 时间可信 | 记录带可信时间戳 | 存在时间戳来源 |
| V5 可关联 | 证据之间可建立关联链 | 存在引用标识 |

### 2.3 有门禁（Gate）

| 要求 | 说明 | 符合性判据 |
| --- | --- | --- |
| G1 变更须声明 | 任何变更先有明确声明 | 存在变更声明 |
| G2 变更分级 | 按影响程度分级处理（修订/功能/主版本） | 存在分级规则 |
| G3 高风险须复核 | 涉及权限扩大/不可逆能力变更须人工复核 | 存在复核记录 |
| G4 可回滚或可拒绝 | 具备回退路径，或明确不可回滚并强确认 | 存在回滚说明或强确认逻辑 |
| G5 放行留痕 | 每次放行产生记录 | 存在放行记录 |

## 第 3 章 变更分级规则（红线）

本规范的核心要求：主版本变更（不兼容）必须重新"上户口"，不得就地升级。

| 变更类型 | 判定 | 处理要求 |
| --- | --- | --- |
| 修订版（文档/文案） | 不改行为 | 注明变更内容，可直接替换 |
| 功能版（新增能力，向后兼容） | 兼容 | 须附变更说明，用户知情后更新 |
| 主版本（不兼容变更） | 不兼容 | 须重新登记户口，旧版本保留可回溯 |
| 权限扩张 | 高风险 | 无论版本号，一律人工复核 |
| 能力卸载/降级 | 中风险 | 须声明影响范围 |

> 红线：智能体不得自主完成对自身的权限扩张或主版本变更。此类变更只能"提议"，放行权归属人类或受权治理机构。

## 第 4 章 户口与证据最小字段集

### 4.1 智能体户口（Manifest）最小字段集

{ "agent_id": "全局唯一标识", "name": "智能体名称", "version": "语义化版本号", "created_at": "ISO8601", "origin": { "creator": "创建者标识", "method": "人工构建\|模板生成\|智能体演化", "parent": "父智能体标识（若为演化生成）" }, "ownership": { "holder": "归属主体", "license": "SPDX 许可证标识" }, "capabilities": ["能力1", "能力2"], "permissions": { "declared": ["声明的权限"], "boundaries": "边界说明" }, "identity_fingerprint": "sha256:...", "upgrade": { "channel": "升级通道地址", "manifest_url": "清单地址", "current_checked_at": "ISO8601" } }

> 说明：upgrade 字段使智能体具备"可寻址的升级能力"——这是后续 SPEC-003 衔接点。

### 4.2 证据工件（Evidence Artifact）最小字段集

{ "artifact_id": "唯一标识", "issued_at": "ISO8601", "issuer": "签发主体标识", "subject": "所属智能体 agent_id", "type": "行为记录\|能力证明\|符合性声明\|评测结果", "payload_hash": "sha256:...", "timestamp_source": "时间戳来源", "verification": { "method": "验真方法", "endpoint": "验真入口" }, "chain_ref": "关联证据标识" }

## 第 5 章 验证与争议处理

### 5.1 验证原则

"有证"的成立条件不是"发布方宣称有效"，而是"第三方可独立验证"。

获取证据 → 计算哈希 → 比对指纹 → 校验时间戳 → 追溯关联链 → 结论

### 5.2 争议处理

当智能体身份或行为产生争议时：

1. 调取户口（Manifest）确认身份与权限边界
2. 调取证据链（Artifacts）复现行为过程
3. 核对放行记录（Gate Records）确认变更是否受控
4. 依价值裁决序论（V1 人的可归责性 → V2 不可逆性设防 → V3 证据可复放）判定

## 附录 A：与 UIBC-MEM 赛道的关系

本规范是 UIBC-MEM（记忆迁移赛道） 的基础评分依据：

- 参赛智能体的户口完整性纳入评测；
- 记忆迁移过程须产生可验证的证据链；
- 跨设备迁移后的身份连续性（同一 agent_id 不变）是核心考点。
