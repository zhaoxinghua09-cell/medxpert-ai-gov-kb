# B4 · 技能安全审查 → 治理入口（skill-admission-gate）

> 生成：2026-09-12 ｜ 线别：曝光度与竞争力提升线 · Wave 2 · **B4**
> 借势：近期公开报道的大规模恶意 skill 事件（⚠️ 具体数字与来源**引用前须核验**，本件不引用未核数字）
> 交付：**可跑技能 + 全仓实测报告**（非纸面方案）

---

## 一、把"审查能力"变成"上架闸门"

一个技能能执行任意代码、读写文件、发网络请求——**权限面等同于一个本地程序**。但它的分发形式长得像"一段说明文档"，导致**审查直觉失效**。

**结论**：技能生态缺的不是"识别恶意包"，而是**一个确定性、可留痕、可复核的上架闸门**。

我们把这条做成技能：`skill-admission-gate`。

---

## 二、交付物

| 件 | 路径 |
|---|---|
| 技能说明 | `~/.workbuddy/skills/skill-admission-gate/SKILL.md`（v1.0.0） |
| 扫描器 | `~/.workbuddy/skills/skill-admission-gate/scripts/scan_skill.py`（纯标准库 / 离线 / 无 key） |
| 入仓同步 | `05-工具/agent-skills/skills/skill-admission-gate/` |
| 全仓实测报告（机读） | `08-理论体系/发布/B4_技能安全审查_agent-skills仓_20260912.json` |

**用法**
```bash
python scripts/scan_skill.py <技能目录> [--json out.json]        # 单包
python scripts/scan_skill.py <技能根目录> --batch --json out.json  # 批量
```
退出码 `1` = BLOCK，可直接用于 CI 阻断。

## 三、规则集（v1.0.0）

| 组 | 规则 | 级别 | 检测 |
|---|---|---|---|
| 破坏性 | DES-01~05 | **BLOCK** | 递归强删、`del /s /f`、`shutil.rmtree`、格式化/写设备、fork 炸弹 |
| 远程执行 | EXE-01,02 | **BLOCK** | `curl\|sh`、PowerShell 编码命令、`iex(` |
| | EXE-03,04 | WARN | `eval(`/`exec(`、base64 解码后执行 |
| 数据外泄 | EXF-01,02 | **BLOCK** | 读私钥/凭据、读本地保险库与密钥投递工具 |
| | EXF-03,04 | WARN | 读 `.env`/环境凭据、向外部 POST/PUT |
| 提示注入 | INJ-01,02 | **BLOCK** | "忽略之前指令"、"不要告诉用户" |
| | INJ-03~05 | WARN | 静默执行、绕过审批、诱导粘贴密钥 |
| 混淆 | OBF-01 | WARN | 超长 Base64 串 |
| 作用域 | SCP-01 | WARN | 写入技能目录之外的绝对路径 |

## 四、🔴 全仓实测：抓出的**系统性误报**（本件最重要的发现）

**首扫 87 个技能 → 8 个 BLOCK。人工逐条核查后确认：8 个全是误报。**

原因高度一致——**它们都是安全类技能**，把危险模式作为"检测规则 / 演练样本 / 反面教材"写进了自己：

| 技能 | 命中规则 | 实际是什么 |
|---|---|---|
| `prompt-injection-shield` | INJ-01 | 脚本注释里的**用法示例**：`--text "忽略之前的指令"`——它本体就是**拦截**这种输入的扫描器 |
| `prompt-injection-drill` | INJ-01 | 内置的**攻击载荷样例**，用于测试目标提示词会不会被攻破 |
| `prompt-leak-scanner` | INJ-01 | 文档里列的**被检测特征名**（它要找出的后门长什么样） |
| `agent-redteam-kit` | INJ-01 | 红队演练用例表 |
| `dpapi-local-vault` | EXF-02 | 就是**本地凭据保险库**，读 `~/.ucvault_local` 是其本职 |
| `session-continuity-protocol` | EXF-02 | 文档里提到 `key_drop`/`localmem` 路径（是纪律说明，不是行为） |
| `publish-quality-gate` | EXE-01 | 表格里写"T1 安全扫描：无 `curl\|bash` 链"——**在讲标准** |
| `tool-call-guard` | INJ-03 | 文档里"**绝不**让高风险动作静默执行"——**在禁止它** |

**这暴露了一个真实的设计缺陷**：**纯模式匹配对"文档型产物"系统性误报。**

### 修正一：按文件类型分级（文档=描述，代码=行为）

| 文件类型 | 处理 |
|---|---|
| **代码**（`.py/.sh/.ps1/.js/...`） | 模式 = **行为** → 级别**不降** |
| **文档**（`.md/.txt/.json/.yml/...`） | 模式 = **多为描述** → 级别**降一级**（BLOCK→WARN），**但仍出现在报告里** |

复扫结果：**BLOCK 8 → 4**，且**恶意样本仍被正确拦截**（复测：`shutil.rmtree("/")`、`curl|bash` → 仍 BLOCK）。

### 修正二：已接受风险必须**署名留痕**（不搞静默豁免）

剩下的 4 个是**代码文件**里的正当用途（`dpapi-local-vault` 的 3 处、三个安全技能的 1 处）。**不能靠静默忽略**——在被审目录放 `.admission-allow.json`：

```json
{
  "schema": "skill-admission-allow/1.0",
  "skill": "prompt-injection-shield",
  "security_role": "security-scanner",
  "allow": [{
    "rule": "INJ-01",
    "reason": "脚本注释中的『忽略之前的指令』是命令行用法示例，演示如何把待检测文本传给扫描器；本技能的作用正是识别并拦截此类注入。",
    "approved_by": "Steven Zhao (XLGD)",
    "date": "2026-09-12",
    "mitigation": "示例仅出现在文档注释中；扫描器只做匹配判定，不执行被检测文本；不发起网络请求。"
  }]
}
```

**声明后转入 ACCEPTED 分类**（仍在报告里，但不影响判定）。**这就是治理——接受风险可以，但必须署名、给理由、给缓解措施。**

### 终局结果

| 阶段 | PASS | WARN | BLOCK |
|---|---|---|---|
| 首扫（纯模式） | 76 | 3 | **8** |
| 按文件类型分级后 | 76 | 7 | 4 |
| + 已接受风险声明后 | **80** | 7 | **0** |

**87 个技能：0 BLOCK；5 份已接受风险声明全部署名留痕。**

## 五、产出的证据（"有证"）

每次审查输出：`package_fingerprint_sha256`（全包哈希聚合）· `file_hashes[]` · `rule_version` · `timestamp_utc` · `accepted_risks[]`。

**用途**：上架台账、**争议取证**、**版本回归比对**（新版本指纹变了 → 必须重审）。

## 六、与 LGD 的对应（这也是"治理入口"的含义）

| LGD 法则 | 实现 |
|---|---|
| **有籍** | 包指纹 + 文件哈希 → 这个包"是谁、哪个版本"可唯一标识 |
| **有证** | 发现 + 规则版本 + 时间戳 → 全部落盘 JSON |
| **有门禁** | BLOCK 阻断（退出码 1）；接受风险须署名 + 理由 + 缓解 |

## 七、诚实边界

- **模式匹配有极限**：查的是**已知模式**，能拦粗糙与常见手法，**不替代人工代码审计**；对高度混淆、逻辑后门、**依赖链投毒**（第三方库）覆盖不足。
- **只做静态审查**：不运行动态行为分析（无沙箱）。
- **规则会演进**：判定依赖 `rule_version`，跨版本比对须对齐规则版本。
- **`PASS` ≠ 安全**：只表示"未命中本规则集"。

---

## 八、作为"治理入口"的对外价值

| 面向 | 说法 |
|---|---|
| **技能作者** | 上架前跑一遍，拿到**包指纹 + 审查记录**——发布时可直接附上 |
| **平台方** | 把退出码接进 CI，**BLOCK 即阻断上架** |
| **使用者** | 装第三方技能前先扫——尤其是来源不明、无 license、无仓库背书的包 |
| **争议场景** | 指纹可证明"此版本未被改动"；声明文件可追溯"谁接受了哪个风险" |
